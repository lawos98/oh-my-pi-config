# Penpot design studio

Primary passive native-design workflow. User intent and the inspected project brief choose product, aesthetic, scope and approval status. This guidance does not install tools, launch helpers or grant access.

## Establish source and access

Read applicable repository instructions, brief, incumbent design and acceptance criteria. Reuse documented decisions; ask only for material information unavailable from those sources. Do not assume a product, stack, local service recipe or generation-plan command.

Discover active `penpot` MCP tools and consult installed API documentation before relying on examples. Confirm actual file/page IDs and object access with a read-only call; documentation success alone does not prove browser connection. Read [setup guidance](../penpot-uiux-design/references/setup-troubleshooting.md) for diagnosis. Missing authentication, connection or supported API is a prerequisite, not permission to substitute raster mockups or an application.

Assign one integration owner and one native writer for the authorized file/page and objects. Recheck IDs before each batch, serialize with manual work, and preserve unrelated objects, identities, assets, component-instance links and token bindings. This is policy, not a hard filesystem, browser, MCP or native sandbox. No account/file scope expansion, publication, library sharing, credential copying or spending without authorization.

## Native work

Use [workflow](references/workflow.md) for briefs, alternatives, systems, journeys and handoff; use [review](references/review.md) for focused rendered review. Inspect existing libraries before adding tokens or components. Prefer native semantic tokens, main components/instances, meaningful state variants, editable text, flex/grid and supported prototyping. Generated art is artwork, not rasterized controls or complete screens.

Before destructive work, use a supported checkpoint/export; if unavailable, stop that destructive operation and report the limit. Additive proposed work may use an explicitly authorized separate page/board. Inspect actual state before retrying uncertain writes; never blindly repeat mutations. Re-read saved structure and rendered output under the assignment's verification policy.

Load only relevant passive references:
- [Library](references/library.md) for licensed templates/assets and provenance; inspect actual availability, fonts and dependencies before reuse.
- `skill://penpot-uiux-design` for secondary component, accessibility and platform references; examples are subordinate to the installed API and this workflow.
- `skill://impeccable` for a selected critique, typography, layout or copy playbook, not its optional code engine.
- [Art direction](references/art-direction.md), [UX writing](references/ux-writing.md), [content stress](references/content-stress.md), or [task walkthrough](references/task-walkthrough.md) when needed by the brief.
- Artwork/toolkit helpers only when explicitly requested and authorized; scripts, installs, command menus and generation-plan workflows are not prerequisites.

## Evidence and handoff

Cover every requested flow/state and acceptance criterion. Return native source IDs, selected/proposed status, source requirements, assets/provenance, relevant exports and preserved edits; provide snapshots through supported authorized controls. Treat collaboration links as private. Distinguish saved native structure, rendered appearance, exercised prototype behavior and unverified runtime behavior. Static design evidence does not establish screen-reader behavior, app performance, platform integration or usability-test success. Design-to-code inspection is read-only unless native writes are separately assigned.
