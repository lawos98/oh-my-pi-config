# Task walkthrough

Define the question and use the current prototype, a consistent starting state and fictional content. Prepare neutral tasks such as finding food logging, explaining a pending activity, or leaving adventure review to return to its source. Avoid naming the expected control in the task.

Distinguish founder preference, agent inspection and observations from actual people. Ask participants what they expect before an action and what changed afterward; avoid coaching unless the task is already blocked. Record observed behavior and exact uncertainty, not invented quotes, timings, conversion rates or participants.

Within the user's requested evaluation scope, summarize the task, board/revision, observation, consequence and possible correction. A small convenience review is directional evidence, not proof for all users. Accessibility/device testing needs the actual relevant implementation and users or methods.

Do not recruit, contact, record or send anything to people without separate explicit instructions. Preparing task scripts and analyzing supplied observations require no contact. Founder acceptance is a recorded decision, not a numerical aesthetic score.
