# Art direction

Use the current chosen or proposed directions, not a new generic style catalog. For each direction identify its visual idea, practical benefit and maintenance cost. Establish material, border grammar, type roles, silhouette, pixel scale, camera and lighting using original or licensed examples.

Make a small editable style board: actual heading/body/action/error copy; one ordinary input; a System panel; an activity row; a representative sprite or material fragment. Show one treatment to avoid. Keep the task and content equivalent across directions. A palette change is insufficient evidence of a different design.

Translate vague feedback into inspectable changes: "too generic" may concern uniform card geometry, stock copy, inconsistent artwork or absent product-specific hierarchy. Ask one focused grill-me question only when the documents and rendered comparison cannot settle the intended tradeoff.

For pixel artwork define size in source pixels, intended display scale, outline/shadow rules, camera, palette, transparency and required views. Inspect animation silhouettes, frame alignment and repeated asset families. Keep text and practical controls native. PixelLab is an optional artwork provider, not the UI source; see pixel-art-pipeline.md.

Deliver a concise visual recipe and actual rendered examples with status and provenance. Do not replace the selected direction with a generic preference for minimalism.
